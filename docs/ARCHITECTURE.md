## Error Handling Contract for Query Functions

Query functions across `src/lib/*.ts` follow one of two intentional
behaviors on DB failure — this is a deliberate split, not an
inconsistency:

| Behavior | Used for | Rationale |
|----------|----------|-----------|
| **Fallback** (wrapped in `safeQuery`, returns empty/default value) | List/aggregate queries rendered inside a Suspense boundary or in the root layout (Navbar) — `getFeaturedArticles`, `getLatestArticles`, `getArticlesByCategory`, `getArticlesByAuthor`, `getRelatedArticles`, `getNavCategories`, `getAllCategories`, `getAllTags`, `sitemap.ts` queries | A DB outage should degrade a section to "no data" rather than crash the whole page or fail the production build (sitemap is prerendered at build time). Safe because there's no ambiguity to introduce — an empty list already has a defined empty state in the UI. |
| **Throw** (unwrapped, propagates to `error.tsx`/`global-error.tsx`) | Single-entity lookups paired with `notFound()` — `getArticleBySlug`, `getCategoryBySlug`, `getAuthorById` | Silently falling back to `null` here would make a DB outage indistinguishable from a genuine 404, which is misleading. These intentionally surface the error boundary instead. |

Session re-validation (`auth()`) and per-user state that depends on it
(`isArticleBookmarked`) are always isolated with their own `.catch()`
when awaited alongside a `safeQuery`-wrapped call in the same
`Promise.all` — otherwise a single failed promise would fail the whole
`Promise.all`, negating the fallback on the other call.

The `safeQuery` helper (duplicated per-file rather than shared from a
common module, matching this codebase's existing per-file pattern)
logs the error via `console.error` before returning the fallback, so
failures are still visible in Vercel/Sentry logs even though they no
longer crash the request.

Background: this pattern was introduced after a production incident
where Neon's free-tier compute quota was exhausted, causing unhandled
`DriverAdapterError`s to crash the homepage, navbar, and the
`sitemap.xml` build step (Sentry issue NEWSPORTAL-P).

## Editorial Workflow

The transition flow for article status (`ArticleStatus`) and the roles authorized for each transition. Admin Override bypasses the normal flow restrictions—it can change any status to any other status without any preconditions.

```mermaid
stateDiagram-v2
    [*] --> DRAFT: Journalists write articles

    DRAFT --> REVIEW: Submit for Review
    REJECTED --> REVIEW: Resubmit

    REVIEW --> PUBLISHED: Approve (Editor/Admin)
    REVIEW --> REJECTED: Reject + catatan wajib
    REVIEW --> SCHEDULED: Schedule (Editor/Admin)

    SCHEDULED --> PUBLISHED: Vercel Cron (when the time comes)

    PUBLISHED --> [*]

    note: REVIEW
        TOCTOU guard (atomic updateMany):
        two editors reviewing simultaneously →
        the second one may receive a 409 Conflict
    end note

    PUBLISHED --> DRAFT: Admin Override
    PUBLISHED --> REVIEW: Admin Override
    PUBLISHED --> REJECTED: Admin Override
    PUBLISHED --> SCHEDULED: Admin Override
```

## Component Architecture

### ArticleCard Variants

| Variant | Used in | Description |
|---------|-------------|-----------|
| `HeroCard` | FeaturedSection | Large card with full-size image, excerpt, and author info |
| `SecondaryCard` | FeaturedSection | Medium-sized card with image, category, and timestamp |
| `HorizontalCard` | LatestSection, SearchResults | Compact horizontal card with a small thumbnail |
| `NumberedCard` | TrendingSection | Ranked card with serial number and number of views |

### Article Query (`src/lib/articles.ts`)

| Function | Description |
|--------|------------|
| `getFeaturedArticles()` | 3 published articles where `isFeatured=true`, sorted by `publishedAt` in descending order |
| `getLatestArticles(page, perPage, includeFeatured?)` | Pagination of published articles. `includeFeatured=false` (default) for the homepage sidebar; `=true` for `/latest` |
| `getTrendingArticles()` | Top 5 articles by views in the last 7 days |
| `getArticleBySlug(slug)` | Single article details + tags (cached using React `cache`) |
| `getRelatedArticles(categoryId, excludeSlug)` | 3 related articles in the same category |
| `getArticlesByCategory(slug, page, perPage)` | Articles by category, default 12 per page |
| `getArticlesByAuthor(authorId, page, perPage)` | Articles by author, default 12 per page |
| `searchArticles(params)` | ILIKE search (supported by pg_trgm GIN index) + category / tag / date filters |

### Bookmark Query (`src/lib/bookmarks.ts`)

| Function | Description |
|--------|------------|
| `getUserBookmarks(userId, page, perPage?)` | All bookmarks belonging to the user, sorted by `createdAt` in descending order, default 12 per page |
| `isArticleBookmarked(userId, articleId)` | Checks whether the article has been bookmarked by the user — a single `findUnique` operation on a composite unique index |

### CMS Queries (`src/lib/cms-articles.ts`)

| Function | Description |
|--------|------------|
| `getUserArticles(userId, page, perPage?)` | All articles owned by the user, sorted by `updatedAt` in descending order, default 12 per page |
| `getArticleForEdit(id, userId)` | A single article owned by the user for the edit form (ownership check) |
| `getReviewQueue(page, perPage?, categorySlug?)` | Articles with the REVIEW status, sorted by `updatedAt` in ASC (FIFO), optional category filter |
| `getArticleForReview(id)` | A single article with REVIEW status for the review detail page; returns `null` if not REVIEW |
| `getAllArticlesAdmin(page, perPage?)` | All articles of all statuses by all authors, sorted by updatedAt in descending order, default 12 per page — specifically for the ADMIN Manage Articles page |

### Query Reading History (`src/lib/readingHistory.ts`)

| Function | Description |
|--------|------------|
| `getUserReadingHistory(userId, page, perPage?)` | All of the user's reading history, sorted by `readAt` in descending order, default 12 per page; an `upsert` in the action ensures each article appears only once |

### Admin Query (`src/lib/users.ts`)

| Function | Description |
|--------|------------|
| `getAllUsersAdmin(page, perPage?, role?)` | All users, sorted by `createdAt` in descending order, default 20 per page, optional role filter |
